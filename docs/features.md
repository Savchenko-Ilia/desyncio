# Features — Module 2: DES primitives

Built on module 1. Concepts follow SimPy (AGENTS.md §1); the API is asyncio-style (D019); interrupts are a
dedicated exception (D020). **Reuse asyncio first (principle 6, D022):** every row says what is delegated to
asyncio. Own waiting/queueing logic only where asyncio has none, built on `asyncio.Condition`/futures.
Common rules for every feature in this module:
- **Virtual time:** all blocking happens in virtual time.
- **Cancellation:** a waiter cancelled or interrupted while queued is removed and leaves no stale reservation. Where we delegate, this comes from asyncio and is tested, not re-implemented.
- **Determinism:** ordering is deterministic (FIFO or `(priority, request order)`), with a same-seed determinism test.
- **Validation:** bad arguments raise `TypeError`/`ValueError` with clear messages.
- **Imports:** each feature is importable from its own module. Top-level exports come only from API-01.

# Module 4: calendar and shifts (D051)

Owner decisions (D051): sim time maps to **real, timezone-aware dates**; a shift that ends while a unit is in use **interrupts** the holder; the module includes both a **calendar** (sim time ↔ dates) and **resources whose capacity follows a shift schedule**.
Common rules:
- Standard library `datetime` and `zoneinfo` (principle 6). Naive datetimes are refused (`TypeError`).
- Sim time stays a float of elapsed time (D004: 1 unit = 1 second unless the calendar says otherwise). The conversion goes through UTC, so a DST change never makes sim time jump or repeat.
- Shift times are local wall-clock times in the calendar's time zone.
- Determinism (principle 2): every scheduling test also checks that the same seed gives the same trace.

# Bug fix: quadratic waiter cancellation (D075)

Reported by Hodos (2026-11-11): cancelling n tasks parked on one primitive takes O(n²), at teardown after `until` and mid-run (a `TaskGroup` abort, a mass interrupt). Reproduced on `integration` d507b48 for `Resource`, `PriorityResource`, `Store`, and for a plain `asyncio.Semaphore`.

Common acceptance criteria for each row: cancelling all n waiters of one primitive (and ending a run at `until` with n waiters) is O(n) or O(n log n) overall; a regression test proves it without flaky wall-clock thresholds (either a deterministic operation count, or a CPU-time ratio between n and 4n with a threshold at least 2x away from both the linear and the quadratic expectation, best of several repeats, under ~2 s total); behaviour is unchanged (FIFO / priority order, no barging, the D023 v2 monitor contract, D030 synchronous release, `ResourceChanged` events, preemption, names); the existing tests and docs examples pass unchanged.
